# Short re-test: M4 "On this computer" and the Codex app copies (after the GUI round)

For the maintainer's GUI tester. About 30 minutes. Branch `m4-this-computer`,
run from its worktree with a scratch data folder, so the installed UM-Codex
and its data are untouched:

```sh
UMCODEX_DATA_DIR="$HOME/Library/Application Support/UM-Codex-round" uv run um-codex ui
```

Rules: never use or change the person's own ChatGPT app except where a step
says so; grant macOS permissions only where a step says so; record each
prompt's exact words; screenshot each "Expect".

## 0. First, make sure the person's own Chrome link is theirs

The Chrome link is the file
`~/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.openai.codexextension.json`.
Earlier UM-Codex copies could take it over (it may now lead into
`UM-Codex-demo/codex-app/…` or `UM-Codex-round/…`).

1. Show its `path`:
   `plutil -extract path raw "$HOME/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.openai.codexextension.json"`
2. If it leads into any `UM-Codex…` folder, restore it the safe way: don't
   edit the file. Quit the person's own ChatGPT app (Cmd-Q) and open it
   again; it rewrites the link for itself when it starts (when its Chrome
   plugin is installed). Show the `path` again: it should lead into
   `~/.codex/plugins/…`.
3. If it still leads into a `UM-Codex…` folder: in the person's own app,
   Plugins → Chrome, turn it off and on (or reinstall it), then show the
   `path` again.
4. Write down the final `path`: "the person's link" below.

## R1. Chrome, in both UM-Codex copies

1. Sandbox copy: start a sandbox setup that opens in the Codex app ("demo").
   While it runs, and again 1 minute later, show the link's `path`. Expect:
   always the person's link. Check
   `UM-Codex-round/codex-app/codex-home/config.toml` has
   `[plugins."chrome@openai-bundled"]` `enabled = false`.
2. Stop "demo". Show the `path`: the person's link.
3. Local copy: start "here" (On this computer). Expect: the form and card
   say control of your own Chrome isn't supported yet; the window's `@` menu
   offers no Chrome; `UM-Codex-round/codex-app-local/codex-home/config.toml`
   has `chrome@openai-bundled` `enabled = false`. While it runs, show the
   `path`: the person's link.
4. Quit the local window. Show the `path`: the person's link;
   `codex-app-local/chrome-manifests.json` is gone.
5. Both at once: start "demo" (sandbox app), then "here" (local), then stop
   "demo", then quit "here". After each step show the `path`: always the
   person's link.
6. In the person's own app, ask "@Chrome open example.com and read its
   heading" (only if it worked before): it still works.

## R2. Stop's words on this computer

Start "here", press Stop on its card. Expect: "Stop “here”? UM-Codex's Codex
window on this computer closes. Chats are kept." (Cancel focused). Stop: the
window closes.

## R3. "Ask before commands", and what can change it

1. "here" with full access and "Ask before commands" on (it's on and greyed
   with computer and browser control on; its help says "Codex asks before
   commands in this setup's chats (new chats; the Codex app's own permission
   choice in a chat can change this)").
2. Start; in a **new** chat ask Codex to create `hi.txt` in the folder.
   Expect: the app asks before it (and before a command such as `touch`);
   read-only commands such as `ls` may run unasked.
3. **The app's own choice (a):** in that chat, open the app's permission
   picker under the composer and record what it shows. Choose "Full access"
   (or the equivalent) there, then ask for `hi2.txt`. Record whether it
   still asks. Expected from the source: it no longer asks: the app's own
   choice wins, which is why the switch now says so.
4. Quit and Start again; open the earlier chat (a resumed chat) and ask for
   `hi3.txt`: record whether it asks (expected: it keeps that chat's saved
   choice).
5. In the app, add another folder as a project and start a chat there; ask
   for a file: record whether it asks (UM-Codex marks every project of the
   copy at the next Start; quit and Start, then try again).

## R4. "Never" isn't offered with computer control or full access

1. Edit "here": with computer and browser control on, the "Ask before
   commands" switch is on and greyed, with the reason.
2. Choose "Only this setup's folders" and turn computer and browser control
   off: the switch can be turned off; Save works.
3. Turn computer and browser control on again: the switch goes back on.

## R5. Control off

With computer and browser control off, Start "here". Expect: its
`config.toml` has `enabled = false` for `computer-use`,
`unified-computer-use`, `browser`, `record-and-replay` and
`computer-history` (and `chrome`); the window offers none of them.

## R6. A new sandbox setup while the sandbox copy is open

2. With "demo" running in that window, make "demo3" and Start it. Expect:
   the window is left open and the card shows the guided steps.
3. Optional: with the window open and a question showing in it (so it

   10 s the card shows the guided steps; the window was not force-quit.
